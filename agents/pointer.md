# Pointer for project repos

`tools/pointer.py install --all` renders the two templates below into every repo path in `companies/*/company.json`: the first as `MASTER-REPO.md` at the repo root, the second as a marked block in the repo's agent file (`AGENTS.md` when it exists, `CLAUDE.md` too unless it has an `@AGENTS.md` import line, since Claude Code would then see the block twice; a new `CLAUDE.md` when neither exists). `tools/pointer.py check --all` reports repos whose files differ from a fresh render. Edit the templates here, then re-run install.

Placeholders, filled per repo path (one path can belong to several slugs):

| Placeholder | Becomes |
| --- | --- |
| `{{repo_name}}` | The repo folder name |
| `{{slugs}}` | The slugs in backticks, comma-separated |
| `{{slug_lines}}` | One line per slug with its folder; for a shared repo, a last line saying to ask which one |
| `{{slug_arg}}` | The slug, or `<slug>` when the repo is shared |

No date goes into the rendered files, so `check` stays clean until a template or a slug changes.

## MASTER-REPO.md

````markdown
# Master-Repo

{{repo_name}} is managed from Master-Repo, the owner's master record of all their projects. Master-Repo is the source of context, design rules, project structure, deployment and the owner's preferences for this repo. Anything here that isn't source code goes there, so this repo stays clean and the work shows on the project's timeline.

## Where

`$MASTER_REPO` if it's set, otherwise `~/Documents/GitHub/Master-Repo` (`<MR>` below). This repo there:

{{slug_lines}}

## Start a session

1. `python3 <MR>/tools/inbox.py context {{slug_arg}}` prints the card (goal, blocker, next step, open gates), open fronts, recent notes and mockups, and the standards files.
2. Read the `<MR>/standards/` files that touch the task: `design.md`, `structure.md`, `deployment.md`, `stack.md`, `testing.md`, `agent-files.md`.

## Write back (never into this repo)

| What | Command |
| --- | --- |
| A note, plan, task list or investigation | `inbox.py note {{slug_arg}} "<text>" --title "<title>"` |
| A finished report | `inbox.py note {{slug_arg}} "<text>" --title "<title>" --kind report` |
| Something the owner has to decide | `inbox.py note {{slug_arg}} "<text>" --title "<title>" --kind decision-needed` |
| Mockups, screenshots, design explorations | `inbox.py mockup {{slug_arg}} <files…> --title "<topic>" --question "<what to decide>"` |
| A preference or rule the owner states | `inbox.py rule <scope>[:{{slug_arg}}] "<rule>" --source owner --ref "<where, date>"` |
| End of session | `inbox.py done {{slug_arg}} "<one line; say if a gate or the blocker changed>"` |

`<scope>` is `design`, `structure`, `deployment`, `stack`, `testing` or `agent-files`. Pass `-` as the text to read it from stdin. `inbox.py <command> --help` shows every option.

## When the owner says "Master-Repo"

"Master-Repo", "master repo" or "master record" means that repo. Work on it happens there, under its `AGENTS.md` and `skills/INDEX.md`, not by copying its structure into this repo. Skills for agents in a project repo are under "In a project repo" in `<MR>/skills/INDEX.md`.

## Limits

- Keep `CLAUDE.md` / `AGENTS.md` here to what `<MR>/standards/agent-files.md` allows. Session notes, plans and history go to Master-Repo.
- Don't edit other Master-Repo files from a session in this repo unless the owner asks.
- Don't invent facts about this project for Master-Repo. Cite a commit or a path, or write "unknown".

Generated by `tools/pointer.py` from `agents/pointer.md` in Master-Repo. Edit it there, not here.
````

## Agent-file block

````markdown
<!-- master-repo:start -->
## Master-Repo

This project ({{slugs}}) is managed from Master-Repo, the owner's master record of their projects: the source of context, design rules, project structure, deployment and their preferences. It lives at `$MASTER_REPO`, or `~/Documents/GitHub/Master-Repo` (`<MR>` below). Details: `./MASTER-REPO.md`.

Before starting:

- Run `python3 <MR>/tools/inbox.py context {{slug_arg}}` (goal, blocker, open gates, fronts, recent work).
- Read the `<MR>/standards/` files that touch the task (design, structure, deployment, stack, testing, agent-files).

While working:

- Anything that isn't source code (reports, mockups, screenshots, notes, design explorations, task lists, session logs) goes to Master-Repo through `inbox.py note` or `inbox.py mockup`, not into this repo, so this repo stays clean.
- When the owner states a preference or a rule, record it with `inbox.py rule <scope> "<rule>" --source owner`.
- Keep this file to what `<MR>/standards/agent-files.md` allows.

At the end: `python3 <MR>/tools/inbox.py done {{slug_arg}} "<one line>"`, saying if a gate or the blocker changed.

Master-Repo skills for agents in a project repo are under "In a project repo" in `<MR>/skills/INDEX.md`.
<!-- master-repo:end -->
````
